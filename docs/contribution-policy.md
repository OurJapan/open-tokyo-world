# 改善の受付・採用ルール

状態：運用方針。ライセンスの付与そのものではない。独自コードMIT、確認済み独自モデルCC BY 4.0を基本案とし、第三者資産の条件は保持する。

## 受付と許諾

気づきの報告・参考URLの紹介には、モデルの提供許諾を求めない。写真は参考利用と素材配布を区別する。他者の成果物の紹介者に所有者である旨を宣言させない。

コード・モデルは採用するファイルと版を固定して、改変・統合・再配布・商用利用を含む対象ライセンスでの提供権限と許諾を確認する。著作権譲渡や運営者だけの独占権は求めない。

外部の公開物は追加部分を含むライセンス、依存素材、作者表示を確認する。公開・Fork可能であることだけで再利用可能と判断しない。不明なら権利者へ確認し、確認までは参照に留める。

## 運営が採用前に記録すること

- 対象ファイル・オブジェクト、取得URL、commitまたはhash。
- 制作者・権利者、作者表示、分かる範囲のAI利用。AI生成だけで権利確認済みとしない。
- コード・モデル・参考資料ごとの条件と第三者素材。
- 許諾の証拠：公開LICENSEのURLと版、または権利者の明示的同意。
- 同意文の版と確認日。非公開の連絡先は公開台帳に転載しない。
- 推定箇所、編集データ、依存関係、再現手順、検証結果。

一般の報告者がすべて記入する必要はない。既に適切な公開許諾がある場合は証拠を保存し、同じ確認を繰り返し求めない。

対象・正式ライセンス確定後の確認文例：

> 私が提供する［対象ファイル・版］を［ライセンス名・リンク］で提供します。そのための権限があり、第三者素材と条件を申告しました。この条件に基づく改変・統合・再配布・商用利用を認めます。作者表示は［表示名］です。

空欄のまま一括同意を取らない。個別ファイルの対象ライセンスが確定していなければ採用を保留する。

## 状態と判断

| 状態 | 運営の作業 |
|---|---|
| 受付 | 対象と改善内容を整理 |
| 追加確認 | 資料・許諾・再現に不足する点を具体的に伝える |
| 作業中 | 範囲を固定し隔離環境で調査・修正・検証 |
| レビュー待ち | 根拠、比較、検証、推定を提示 |
| 採用 | 人間が判断し関連Issue・PR・作者・出典を記録 |
| 保留／見送り | 理由と再検討できる条件を説明 |

これは運用上の状態であり、GitHubラベル・自動化の実装済みを意味しない。品質・根拠・権利・再現性・保守負担で判断する。判断が変わった際に記録し、採用や納期は保証しない。

## 事業とコミュニティ

公開成果を独占販売する方針は取らない。運営者は制作・更新・配信・支援等の有料サービスに活用でき、参加者も対象ライセンスに従い商用利用できる。自動の報酬・売上分配はなく、有償案件は別途合意する。顧客への納期付き業務を無償参加者の義務にしない。

貢献紹介の掲載希望とライセンス上必要な表示は区別する。公開Issue・PRの履歴の匿名化は約束しない。作者・出典・ライセンス・変更履歴を保持する。
