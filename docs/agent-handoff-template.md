# 運営からAIへの引き継ぎ書式

運営またはAIが作業メモへコピーして埋めます。一般の報告者への必須フォームではありません。不明な値は「不明」、不要なものは理由付きで「対象外」と記載します。空欄を推測で埋めません。これは自動実行用ファイルではありません。[運営手順](maintainer-workflow.md)

## 受付と依頼

- 作業名：
- Issue / 元の依頼への参照（練習は練習と明記）：
- 参照した内容と時点（後続コメントを含むか）：
- 依頼する運営者 / 担当AI / レビュー担当：
- 種類：調査のみ / 現実との差分修正 / 文書・機能 / 練習・表現調整
- 今回の目的と対象（一件・一か所を基本にする）：
- 許可済みの作業と公開範囲：

## 入力と変更範囲

- 起点のrepository・commit：
- 対象feature / part / object / 文書：
- 入力の場所・版・hash（公開スターターならコードのcommit。従来の都市なら固定blend等）：
- 担当者が入力を取得できるか：
- 使用する既存CLI・adapter（存在するものだけ）：
- 変更してよいファイル・対象：
- 対象外として保持するもの：
- 根拠URL・観測時点・確認日：
- 既存の許諾記録と適用範囲（同じ同意を再取得しない）：
- 新たに確認が必要な点・推定箇所：

## 完了条件と検証

- 何が確認できれば今回完了か：
- 実施する検証・比較視点・設定：
- 比較を省略できる理由（調査のみ・文書など）：
- 実行時間・費用等の上限（指定がなければ既存運用の範囲と明記）：
- 再試行上限（初期目安：実装修正2回、render再試行1回。人間の新たな追加指示は別に記録）：
- 上限到達時に残すもの・次に判断する人：
- 提出物と保存先・公開できる範囲：

## 結果を追記

- 状態・判断理由：
- 実行したコードのhead / hashと使用入力：
- 根拠、比較、検証結果へのリンク：
- PR（ソース差分のない練習や調査のみなら作成しない場合もある）：
- 人間のレビューと追加指示：
- merge commit / 採用成果物（未取り込みなら未取り込み）：
- 残った課題・次の担当・再開条件：
