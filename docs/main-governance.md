# mainの保護と承認責任

## 責任と権限

AIを利用した変更・レビュー・承認・マージを含め、アカウントを通じて行われた操作の責任は、そのアカウント保有者が負います。Maintainerは、承認する変更が採用基準を満たすことに責任を持ちます。AIへの依頼・許可の範囲を超える操作は認めません。

承認者は `OurJapan/maintainers` で管理し、当初のメンバーは `ark4ez` のみです。メンバーの追加・削除は当面 `ark4ez` が管理します。マージも当面 `ark4ez` の責任で行います。これは担当の運用規則であり、承認権限とマージ操作権限は同一ではありません。Organization ownerや管理者が設定を変更できる点は残ります。

## GitHubの保護

mainを対象に次の2つのRulesetを併用します。

| Ruleset | 内容 | バイパス |
|---|---|---|
| main-baseline | PR必須、GitHub Actionsの `contracts` 成功、レビュー会話の解決、force push・削除禁止、Squash merge | なし |
| main-maintainer-review | 全ファイルにmaintainersから1人の承認必須、追加変更で古い承認を失効 | main-review-exceptionチームにPR経由のみ許可 |

承認の免除で基本保護は免除されません。必須チェック名やCIを変更するときは設定との整合を確認します。マージ後の作業ブランチは自動削除します。CIは実物精度や素材の利用条件を保証しません。都市変更は同条件Before/After、Validation、出典・推定・利用条件を確認します。文書変更は内容・リンクを確認します。

## 単独承認者の期間の例外

GitHubではPR作成者は自分のPRを必須承認できません。承認者が1人の期間は、`ark4ez` が本人名義のPRについて必要な検証と差分確認を行い、以下の記録をPR本文に残して承認要件をバイパスし、マージできます。AIによる操作も本人の依頼・許可と責任の範囲内で行います。

```text
例外理由：承認者が1人の期間の本人PR
責任者：ark4ez
確認対象head SHA：
差分確認・検証結果：
未確認事項・採用判断：
```

例外チーム `OurJapan/main-review-exception` のメンバーは `ark4ez` のみとし、maintainersに人を追加しても例外権限は付与しません。GitHubのバイパスは本人PRだけに技術的に限定できないため、他人のPRへの使用はこの運用では認めません。例外権限は承認を偽装するものではなく、承認要件の免除として記録します。

本人不在時は取り込みを保留します。承認者が2人になった時点で例外の廃止を見直します。承認後に変更が入った場合は、通常承認・例外とも新headで必要な検証と判断をやり直します。
