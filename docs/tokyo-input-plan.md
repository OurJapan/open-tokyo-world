## 既存シーンの実検査

採用済み `candidate.blend` をBlender 4.5.1 LTSで自動実行を無効にして読み取り検査した。SHA-256は `98a3932e6dc972d4ae702d264c1e894d77765a9a3a5e57c8a75591eafd42e926` で採用記録と一致した。保存処理は実行していない。

- メッシュオブジェクト：3,255。画像データブロック：384、うち埋め込み383。リンクライブラリ：0。
- PLATEAU名の2コレクションに63＋365メッシュ。材質参照画像はそれぞれ87・295。この数は元地物数やユニーク建物数を意味しない。
- 東京タワーの既存3コレクションには4＋13＋15メッシュ。森JPの既存4コレクションには4＋12＋15＋4メッシュ。今回の材質ノード検査では画像依存を検出しなかった。
- 別コレクションには `facade_atlas.png` の参照がある。画像がない建物でも、形状の出典やコードの許諾が確定したとは限らない。

この検査はオブジェクトの材質ノード内の画像参照を対象とする。World・Compositor等の全依存、各メッシュの完全性、全画像と公式ファイルのバイト照合は未確認。[要約記録](tokyo-input-audit.json)に検査範囲を残す。元の977 MBシーンの画像台帳だけで現在の559 MBシーンを説明しない。

## PLATEAUの確認結果

[港区2025データセット](https://www.geospatial.jp/ckan/dataset/plateau-13103-minato-ku-2025)と[3D Tiles/MVTの個別リソース](https://www.geospatial.jp/ckan/dataset/plateau-13103-minato-ku-2025/resource/08755b94-7b2e-4c9c-bf35-6c4d0768a463)をブラウザで確認した。個別リソースはPLATEAUサイトポリシーに従うと表示され、圧縮ZIPは約1.7 GBと記載されている。データセットの年度は観測日や全地物のLODを保証しない。

[サイトポリシー](https://www.mlit.go.jp/plateau/site-policy/)は出典と加工表示を求め、個別権利表記や法令上の制約にも言及している。公式データを選定できる根拠と、旧シーンの混在画像・加工履歴が全て確認済みであることは別である。新しい入力には公式ファイルの出典・利用条件・加工内容を引き継ぐ。

既存広場の位置の根拠である `data221.b3dm` を公式配信から再取得し、保存済みのハッシュと照合する。全区ZIPを参加者に必須とせず、この1タイルと必要な階層情報から試す。配信終了・ハッシュ不一致時に別年度や最新版へ自動で差し替えない。

## 最初に再構築する範囲

最初の試験単位は「森JP入口広場6部品＋隣接するPLATEAUの1タイル」とする。東京タワー周辺というQuality Area内の最小技術試験であり、東京タワー本体を含む一区画の完成配布ではない。地理的な境界・含む建物ID・置換対象はタイル解析後に確定する。タイル内の全地物を森JPタワーとみなさない。

1. タイルの親tileset・transform・RTC・batch属性を取得し、必要ファイルのURL・容量・ハッシュと地物IDを固定する。GLBに外部依存があれば列挙する。
2. 既存広場のローカル座標と元の地理座標を照合する。旧取込は建物底面を個別にz=0.32へ移動しているため、高さをそのまま測量値として扱わない。
3. 必要な取込コードの由来・許諾を確認し、版固定の取得・検証・取込コマンドを作る。広場だけに認められたライセンスを都市全体へ拡張しない。
4. 非同梱の旧blend・NPZ・個人PCのキャッシュを使わず、新規フォルダーで取得からBlender保存・再オープン・画像生成まで実行する。出典と未確認事項を同梱する。
5. 人間が座標・形状・重複・表示を確認し、最初のArea候補を採用する。その後、東京タワー・森JPの独立モデルを一つずつ追加する。

出口条件は、入力一覧に不明なURL・ハッシュ・利用条件・必須変換がなく、取得失敗を明示でき、同じ版から同じ対象を再構築できること。現段階では未達である。

## 保存方法と次の作業

今はコードと台帳をGit、広場パッケージを既存Release、PLATEAUを公式配信に置く構成で進める。新しいクラウド契約や都市blendのアップロードは不要。元データの保存コピーを再配布する場合は対象条件と容量を確認してから別途決める。

次の実装は上記1・2の「1タイルの依存関係と座標の確定」。東京全域のタイル選定や追加モデリングには広げない。新規参加者の利用テストと独立バックアップは引き続き別の未完了項目として管理する。
