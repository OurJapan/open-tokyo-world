# 飯田橋・9月8日の撮影テスト

公開URL： https://ourjapan.github.io/open-tokyo-world/?area=iidabashi

## 出発前（通信できる場所で）

1. iPhoneのSafariで上のURLを開き、見出しが「飯田橋駅付近（千代田区側）」であることを確認します。
2. 「オフライン撮影の準備ができました」が出るまで待ちます。同じSafari・同じURLを当日も使用してください。プライベートブラウズは使わないでください。
3. カメラを開き、カメラ・位置・方位を許可して1枚試し撮りします。メモを書き、「端末に保存して次の写真へ」を押します。
4. ページを再読込し、保存一覧から写真とメモが戻ることを確認します。
5. 参加用コードは「iPhone対応Web AR PoCを設計」タスクで案内されたものを用意します。コードを写真や公開メモに写さないでください。

## 現地で

「カメラを開く」→「写真を撮る」→分類・メモ→「端末に保存して次の写真へ」を繰り返します。写真は撮影後、メモは入力後約0.5秒で端末に保存します。「次の写真へ」「閉じる」でも保存完了を待ちます。保存失敗の表示が出た場合は、その写真をZIPで取り出してから移動してください。

保存一覧から写真を開き、参加用コードと保存への同意を入力して「送信する」を押します。「受け付けました」と受付番号が出れば受付完了です。送信後も端末の写真は残ります。コードはブラウザ内に保存しないため、別の写真では再入力が必要です。

通信が切れても端末保存はできます。送信が失敗したら写真を残し、接続が戻ってから一覧で開いて再送してください。送信開始後は内容を固定し、再読込しても同じ受付ID・同じ内容で確認します。送信内容を変えたい場合は別の写真記録として作成してください。

テスト終了後に各写真の「ZIPを共有・ファイルに保存」または「ZIPをダウンロード」を使ってバックアップします。ZIPには生写真・観測JSONが入ります。共有画面を閉じただけでは保存完了とは限らないため、iPhoneの「ファイル」で確認してください。ブラウザのデータを消去すると端末保存分も消えます。

## 位置と表示

最初は「目の前に表示」で撮影できます。「現在地に合わせる」を試す場合は表示範囲300mを選びます。仮の原点は緯度35.7009、経度139.7450。駅付近の千代田区側を対象とする手動設定で、測量点・駅入口・建物位置ではありません。300m円は区境で切り取っていません。原点から300m以内、位置誤差50m以下、新しい北基準の方向がある場合に概略表示します。

3Dは独自の検証モデルです。飯田橋の実街並み、VPS、正確な位置補正、AI自動修正は未実装です。写真には3Dを合成しません。撮影時のGPSが不明なら位置なしで保存し、推測位置を記録しません。

## 写真の受付

接続先： https://otw-observation-api.open-tokyo-world-observation-api.workers.dev

写真は非公開で受付。1枚5MB、全体で1日30件・月300件・保存合計2GB、保存から30日後に順次削除します。送信成功とAI修正の実行は別です。API側の運用は `web/observation-api/README.md` を参照してください。端末側の削除はサーバー保存済み写真の削除にはなりません。

## 実装と検証

ブランチ：`feature/iidabashi-field-test`。対象エリア設定は `areas/iidabashi/field-test.json`、生成は `python adapters/open-tokyo-world/build_web_fixture.py`。駅位置の参考： https://place.0rz.org/station/1131316 。原点は現地未確認です。

`web/spatial-viewer` で `pnpm install --frozen-lockfile`、`pnpm test`、`pnpm build`。公開ビルドは環境変数 `VITE_OBSERVATION_API_URL` に上記API URLを設定します。参加用コードをビルドに含めないでください。

ブラウザ検証は `pnpm exec playwright install chromium` の後、API URL設定付きビルドを4181番でpreviewし、`pnpm test:browser`。実ブラウザのIndexedDB・Service Worker・擬似カメラで、連続撮影、メモ保存、再読込復元、ZIP、オフライン再読込と撮影、送信失敗後の同一内容再送、受付番号復元、選択写真の削除、容量不足時のZIP救済を確認します。送信APIはこのブラウザ試験では模擬応答で、個人写真を送信しません。

iPhoneの実カメラ・位置・方向、OS共有画面、長時間動作は実機での確認が残ります。出発前の1枚テストで確認してください。
