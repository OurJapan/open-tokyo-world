# 別PCを用意せずに参加環境を検証する

公開された森JP周辺と共通素材は、GitHub Actionsの新しいWindows／Linux仮想マシンで検証できます。個人PCを検証サーバーとして公開したり、追加のPCを購入したりする必要はありません。通常の契約テストとは別の `Contributor environment` ワークフローです。

## 確認する内容

1. コードを取得し、公式のBlender 4.5.1をダウンロードします。配布アーカイブのSHA-256を[公式チェックサム](https://download.blender.org/release/Blender4.5/blender-4.5.1.sha256)で固定しています。
2. 空の作業先と専用のBlender設定フォルダーを作ります。制作データのキャッシュは復元せず、GitHub認証情報・Pythonユーザーパッケージ・個人のBlender設定に依存しない実行条件を用います。
3. 地区CLIで森JP周辺と共通素材を公開URLから取得し、サイズ・ハッシュを照合します。森JP周辺42メッシュと共通素材16メッシュを開き、CPUで4視点のBefore/Afterを描画します。
4. オフライン再実行で取得0 bytes・同じ生成済みモデルの再利用を確認します。
5. 編集用コピーと出典・許諾文を用意します。さらに試験専用の別ファイルで1頂点を0.125m動かして保存し、別のBlenderプロセスで変更が残ること、メッシュ・UV・変換・材質スロット・同梱画像の状態が保存前と一致することを確認します。
6. 基準モデル・最初の編集用コピー・共通素材が書き換わっていないことを確認します。試験用の変更は街の改善案として採用しません。

対象は公開している森JP周辺と共通素材です。非公開の旧都市や地図、個人PCの制作フォルダーは入力に使いません。生成モデルや画像はCIの成果物として配布せず、JSONの検証結果と診断ログだけを14日間保存します。

## GitHubで実行する

リポジトリの **Actions → Contributor environment → Run workflow** から実行します。権限のある利用者が対象のブランチを選べます。ワークフロー、検証スクリプト、地区CLI・台帳・森JP生成に関係するファイルを変更するPRでも自動実行します。実行時間の上限は各OSで25分です。

[GitHubの標準ホステッドランナー](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners)では、今回選択したWindows／Ubuntuジョブごとに新しいVMが用意されます。成功時の `report.json` にOS、実行URL、構成ID、実行コードのハッシュ、取得量、編集・保存・再読み込みの結果を残します。失敗した場合も診断ログを確認できます。既存のmain保護にある `contracts` は変更しません。

## このPCだけで先に試す

Python 3.11/3.12から次を実行できます。`BLENDER` はBlender 4.5.1の実行ファイルに置き換えてください。

```text
python tests/contributor_smoke.py --blender BLENDER --output data/local/contributor-check-01
```

Pythonを別に用意していないWindowsでは、Blenderに付属する `4.5/python/bin/python.exe` を指定します。出力先には毎回新しいフォルダーを指定してください。既存の出力先は拒否します。コードの別コピーや公開ソースZIPの展開先を試す場合は `--repo PATH` を加えます。

ローカル実行も新しいデータ・Blender設定で試せますが、同じOS・ハードウェアを使用します。フォルダーを分けることはOSのアクセス制限による隔離ではありません。[実行結果の記録](contributor-environment-verification.json)

## この検証の範囲

新しい環境での公開データ取得、生成、CPU描画、プログラムによる編集・保存・再読み込みを確認します。マウス操作での使いやすさ、GPU表示・性能、別PCでのレンダー画素の完全一致、街全体の配布・自動組立・現実との一致は対象外です。初参加者による操作確認は、協力者が参加できる時点で追加できます。
